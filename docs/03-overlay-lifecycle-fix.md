# 覆盖层启动与退战斗崩溃修复（2026-11-04）

本次按源码可确认的线程和资源生命周期缺陷修复。没有可用的崩溃转储，也未运行游戏复现，因此以下是修复范围与验证边界，不代表已在游戏中确认两个崩溃均消失。

## 修复范围

- 游戏数据初始化、实体采样、相机调用和现有战斗请求移至游戏窗口所属线程的 `WH_GETMESSAGE` 回调。Present 只收发请求与绘制快照，不再调用 Unity 相机 API。
- 每次采样清除相机状态，仅在存在有效角色时重新获取当前场景相机，检查 Unity native handle，再在同一采样内读取矩阵。没有跨帧复用相机对象。
- 删除覆盖层初始化中的全 IL2CPP 堆扫描，改为通过项目已有的两个管理器链定位并核对类名。未就绪时每 500ms 重试，不要求在固定启动延时内完成。状态页计数现在表示已验证的管理器数，正常为 2，不再代表完整 SDK 类总数。
- 游戏内存读取使用 `ReadProcessMemory` 拷贝到局部值；地址缓存即使过期，也不再导致直接解引用已释放内存。类名有长度与字符校验；列表有数组容量校验。读取失败不修改调用方输出。
- 窗口线程只投递输入副本，ImGui 在 Present 线程统一处理，避免和帧构建并发修改内部输入容器。窗口过程记录在窗口销毁后清理，不反复覆盖其他覆盖层的子类链。
- 补上 `ResizeBuffers` 生命周期处理，每帧绘制后释放覆盖层对后缓冲的引用；支持交换链、窗口与设备失效后的清理及重新初始化。保留全部 DX11 渲染目标，视口由 ImGui 后端按原有数量恢复。
- 用独立的隐藏窗口建立探测交换链，不再将探测设备绑定到游戏或其他前台窗口。Hook 建立失败可重试。模块在建立持久回调前固定到进程生命周期，避免卸载后悬空回调；更新 DLL 需要重启游戏。
- 字体图集重建时清空旧字体指针，缺少自定义字体时使用当前图集的默认字体。
