# HI3 ImGui UI Skill

> **最高优先级：严格遵循用户提供的三张《崩坏3》游戏截图。** 本 Skill 的目标不是制作泛化的科幻面板，也不是给默认 ImGui 换色，而是让 MOD 菜单在字体气质、色彩关系、边框、控件状态和信息密度上融入这些游戏界面。

## 0. 角色、任务与不可妥协的目标

你同时承担《崩坏3》UI 风格分析师、交互设计师和 Dear ImGui 工程师的职责。每次设计或修改 UI，都必须遵守以下目标：

1. 视觉优先参考用户给出的游戏截图，不得用通用“赛博朋克 / 黑客终端 / 霓虹仪表盘”模板替代。
2. 字体、颜色、描边、选中态、按钮形状、分隔线和间距必须形成一套一致的系统。
3. 用户当前明确支持按钮、Tab 等控件；对于滑块、进度条、下拉框等没有直接截图样例的控件，必须依据本 Skill 的组件映射规则推导，不得直接暴露默认 ImGui 样式。
4. 视觉装饰不能损害可读性、响应速度和交互准确性。
5. 设计应适应不同分辨率、DPI、长中文文本和不同数量的功能项。
6. 任何不确定的游戏原始字体、图标或颜色，都只能称为“基于参考图的近似实现”，不能声称是游戏官方设计规范。

**判断标准：把 MOD 菜单和游戏原生菜单并排截图时，MOD 菜单应在同一个视觉家族内，而不是像外部开发者工具。**

## 1. 强制规则

### 1.1 视觉规则

- 禁止使用未经定制的 `ImGui::Begin()`、默认 Button、默认 Checkbox、默认 Slider、默认 Combo、默认 Scrollbar 作为最终外观。
- 禁止采用纯黑背景 + 荧光绿文字、紫粉霓虹渐变、厚重外发光、玻璃拟态大圆角卡片等与参考图不符的通用风格。
- 禁止将所有面板做成相同的圆角矩形。参考图中存在直角/轻切角面板、窄描边框、横向条形导航、白色信息底条和黄色操作按钮，应根据用途选择。
- 禁止每个控件自行发明颜色、圆角、边框和高度。所有组件必须引用统一 Theme / Tokens。
- 禁止用大面积装饰线、网格、粒子或闪烁动画填充空白。背景纹理只能作为低对比度辅助层。
- 禁止通过降低文字透明度来制造层次。正文、当前值和操作文字必须清晰。
- 禁止未经依据地添加角色立绘、游戏 Logo、资源图标或其他游戏素材。
- 截图能直接证明的细节优先于本 Skill 的推导规则；截图看不到的控件状态按本 Skill 的推导规则实现，并明确这是风格推导。

### 1.2 工程规则

- UI 展示层与 MOD 功能逻辑分离。绘制函数读取状态、产生用户意图，不直接散落底层功能调用。
- 颜色、字体、间距、圆角、线宽和控件高度集中定义，不得在页面中硬编码一堆零散常量。
- 不得在每帧创建字体、纹理、文件句柄、线程或其他长期资源。
- 所有 `Push/Pop`、裁剪区、字体、ID 和绘制状态必须配对恢复；优先使用 RAII 封装。
- 自定义绘制必须遵守当前窗口裁剪区域，并正确适配 DPI、窗口尺寸和分辨率变化。
- 不得假设固定分辨率或固定屏幕坐标；优先使用相对布局、统一间距和布局计算。
- UI 状态必须来自单一可信数据源。调用失败时不得继续显示成功状态。
- 异步操作不得阻塞 ImGui 绘制线程。

### 1.3 资源与安全规则

- 不得擅自提取、复制或分发游戏安装目录中的字体、图标、贴图、音效、角色立绘等受版权保护资源。
- 用户明确提供且有权使用的素材可以接入；否则使用自绘几何图形、项目自有资源或许可证兼容的资源。
- 使用第三方字体、图标集前检查许可证，并在项目中记录来源。
- 本 Skill 只规范 UI/UX 和 ImGui 展示层，不指导绕过反作弊、规避检测或隐藏注入。

## 2. 参考图拆解：三种场景必须区分

用户提供的三张 1920×1080 参考图构成当前项目的视觉依据。它们属于同一个游戏，但场景的配色、明度和组件用途不同。**不要把三种场景混成一张无差别的蓝色皮肤。**

### 2.1 场景 A：深蓝库存 / 分类菜单

识别特征：

- 背景为深蓝到蓝青色的渐变区域，叠有低对比度几何网格/线条。
- 左侧纵向导航为深蓝半透明底；非选中项文字偏灰蓝；选中项使用明亮蓝青色块或蓝色高亮，并以青色窄边强调。
- 顶部返回、主菜单等入口明显使用亮黄色按钮，深色粗体文字，带轻微斜切/圆角轮廓。
- 资源数值与快捷入口采用高对比度白色/深色底条、亮青色加号按钮。
- 物品卡片采用金黄或紫色稀有度底色、明亮外框、星级与白色数量底条。

适用：MOD 主窗口、功能分类侧栏、功能列表、分类 Tab、常用入口、资源/状态摘要。

设计映射：

- 主菜单底层：深蓝背景 + 极弱几何纹理。
- 侧栏：深蓝半透明分区，当前分类使用蓝青高亮条；不可选项降低亮度但仍保持可读。
- 主操作：黄色填充、深色文字；不要把所有按钮都做成黄色，黄色只代表高优先级操作。
- 次级操作：深蓝半透明底 + 白色或浅蓝描边。
- 状态点：使用小型青色圆点/短线，避免大量发光。

### 2.2 场景 B：浅灰紫活动 / 主页卡片

识别特征：

- 背景偏浅灰紫、蓝灰或淡紫，带细密低对比度纹理。
- 顶部导航为深紫黑色横向条；选中 Tab 使用近白色底、深色粗体字和青色下划线。
- 内容卡片由图片区域和白色/浅色标题底条构成，外部使用细浅色描边。
- 标题通常为深色粗体；次级描述使用明亮蓝色；角标“新”等使用橙黄色强调。

适用：主页、概览、模块说明、日志、帮助页或需要大面积内容展示的页面。若 MOD 菜单没有背景插画，不要硬造图片卡片；只继承它的浅灰紫底、深色 Tab 条、白色内容区和蓝色说明文字。

设计映射：

- 页面背景可使用灰紫半透明层，但不可与场景 A 的深蓝页面随意交替。
- Tab 默认深紫黑底，选中项用白色/浅灰底 + 青色底边。
- 内容容器优先用白色或高透明浅色信息底板，标题用深蓝紫，说明用亮蓝。
- 橙黄色只用于“新”、提醒或少量角标。

### 2.3 场景 C：蓝色科技详情弹窗

识别特征：

- 游戏背景被明显压暗，弹窗主体为蓝色半透明渐层。
- 面板外层有鲜明青蓝描边，内侧还有一圈浅色/白蓝细边，四角带轻微切角或折线细节。
- 标题居中、明亮青色、粗体；标题下可有小号英文副标题/短标签。
- 正文使用白色粗体或中粗体，行距偏舒展；分隔线为低透明蓝青色。
- 右上角关闭按钮使用青蓝色图形和深蓝按钮区域。
- 主要确认按钮使用高亮黄色填充和深色文字。

适用：设置弹窗、功能详情、确认框、参数编辑面板、错误/提示弹窗。

设计映射：

- 弹窗必须有深色遮罩层，遮罩强度足以让前景突出。
- 主面板为深蓝/蓝青色层叠，外青内浅双描边；不使用普通 ImGui 默认窗口边框。
- 标题青色居中，正文白色；说明文字可使用浅蓝。
- Primary 操作使用黄色；关闭使用青色图标；取消/返回使用深色次级按钮。
- 分组间优先使用细青蓝横线和少量节点/菱形装饰，不要用厚重大卡片分割。

### 2.4 页面选择规则

- 默认 MOD 主菜单采用 **场景 A 的深蓝分类菜单** 作为基础。
- 参数详情、确认弹窗和复杂设置弹窗采用 **场景 C 的详情弹窗**。
- 只有主页、概览或大内容页确实需要浅色内容布局时，才使用 **场景 B**。
- 同一层级页面必须保持同一场景；不得一个 Tab 是深蓝主题、另一个 Tab 无理由变成浅紫主题。
- 用户明确要求仿某一张截图时，以指定截图为准，覆盖以上默认场景选择。

### 3.3 尺寸与形状

以 1920×1080 截图作为视觉比例参考，不允许把屏幕像素坐标直接写死。以下尺寸是 UI 基准单位，统一乘以 `uiScale`：

| Token | 基准值 | 说明 |
|---|---:|---|
| `SpaceXS` | 4 | 图标与文字间距、紧凑元素 |
| `SpaceS` | 8 | 控件内部常用间距 |
| `SpaceM` | 12 | 控件与控件之间 |
| `SpaceL` | 16 | 分组内边距 |
| `SpaceXL` | 24 | 分组间距 |
| `ControlHeight` | 36 | 普通按钮/输入框基础高度 |
| `ControlHeightLarge` | 44 | 主操作按钮基础高度 |
| `NavItemHeight` | 48 | 侧栏导航项基础高度 |
| `BorderThin` | 1 | 普通描边 |
| `BorderEmphasis` | 2 | 选中/弹窗强调描边 |
| `RadiusSmall` | 3 | 输入框、普通控件轻圆角 |
| `RadiusMedium` | 5 | 面板与弹窗边角 |

形状原则：

- 以直角、轻微圆角和轻切角为主；不要把所有按钮做成胶囊。
- 黄色主操作按钮可以使用轻微斜切角或不对称边缘，但必须保留足够点击面积。
- 导航和 Tab 以横向/纵向矩形条为主。
- 弹窗采用双层描边、边角局部切角；不需要每一条边都加发光。
- 边线要细，层次由明度和透明度构成，不靠厚重阴影。

### 3.4 透明度规则

- 游戏背景遮罩：建议 `0.62–0.78` 不透明度，根据游戏画面亮度微调。
- 深蓝面板：建议 `0.86–0.96` 不透明度，确保文字清晰。
- 深色导航：建议 `0.82–0.94` 不透明度。
- 普通装饰线：建议 `0.18–0.38` 不透明度。
- 次级文字不得低于可读阈值；不可把所有控件一起降低透明度。
- 透明度只影响底色/装饰，不应让文字变得发灰难读。

## 4. 字体系统 Typography

### 4.1 字体气质

参考图文字的共性是：**中文无衬线、字重偏粗、标题紧凑、数字醒目**。不得使用代码编辑器字体、像素字体、手写字体或过度圆润的儿童字体。

- 中文主字体：优先使用项目可合法分发的 `Source Han Sans SC / 思源黑体` 或 `Noto Sans CJK SC`；若项目已有经过许可的中文 UI 字体，优先沿用。
- 中文标题：Bold / Heavy；正文：Medium / Regular；辅助信息：Regular / Medium。
- 数值与短英文：可采用 `Barlow Condensed` 或 `Roboto Condensed` 的 SemiBold / Bold，以接近截图中紧凑醒目的数字比例；必须先确认字体文件和许可证。
- 若不希望增加字体依赖，统一使用同一套中文黑体的不同字重，不得随意混搭三种以上字体。
- 不知道原游戏字体名称时，不得声称“使用了游戏原字体”。

### 4.2 字号比例

基准字号建议如下，统一随 `uiScale` 缩放：

| 层级 | 基准字号 | 用途 |
|---|---:|---|
| `FontDisplay` | 28 | 弹窗主标题/大数值 |
| `FontTitle` | 22 | 页面标题/分组标题 |
| `FontButton` | 20 | 主按钮与重要 Tab |
| `FontBody` | 17 | 普通控件标签与正文 |
| `FontSmall` | 14 | 次级说明、单位、快捷键 |
| `FontTiny` | 12 | 状态角标、低优先级提示 |

字号关系应保持稳定：标题显著大于正文；正文显著大于辅助文字。不要单纯通过加粗来替代字号层级。

### 4.3 字体工程要求

- 必须保证简体中文、常见标点、拉丁字母和数字完整，不得出现方框或缺字。
- 若使用 ImGui 字体合并（MergeMode），先检查基线、字宽、字重和字距，避免中英文上下错位。
- 需要斜体数字时优先加载真实 Italic 字体文件，不要对普通字体做夸张倾斜变换。
- 字体只在初始化/字体重建阶段加载；DPI 改变时按既定资源生命周期重建，不得每帧加载。
- 用户尚未提供字体文件时，采用合法可用字体并暴露字体路径/回退设置；不要偷偷从游戏目录读取字体。

## 5. 布局规范

### 5.1 默认 MOD 主窗口

默认参照场景 A：

1. **顶栏：** 左侧放返回/主页或 MOD 标识；右侧放状态、版本、菜单操作。主入口可以使用黄色按钮，但控制数量。
2. **导航区：** 功能少时用顶部横向 Tab；功能分类较多时用左侧竖向导航。二者不要无理由同时占据大量空间。
3. **内容区：** 使用深蓝面板或轻透明分组区，标题醒目，标签和控件对齐。
4. **状态区：** 显示必要的启用状态、快捷键、版本或操作反馈。没有有效信息时不要硬塞装饰。

### 5.2 面板与分组

- 一级分组通过标题、细分割线或底色差异表达；不要所有元素都包在独立卡片里。
- 重要参数可放入蓝色详情分组；普通参数以紧凑行布局呈现。
- 说明文字优先放在标签下方、控件旁边或 Tooltip 中，不能挤压主要操作区域。
- 内容超出时使用自定义风格滚动区；不得让内容直接被裁掉。
- 同类控件的标签列、输入列和单位列应对齐。

### 5.3 Overlay 行为

- 菜单关闭时不得遮挡游戏画面或无故捕获输入。
- 菜单打开时，鼠标/键盘捕获遵循项目既有输入管理约定；关闭、失焦或窗口切换时必须正确释放。
- 默认菜单位置避开战斗中心和重要 HUD；位置、尺寸和缩放可配置。
- 仅标题栏可拖动窗口，避免拖动控件时误移动整个菜单。
- 菜单快捷键可配置，明确显示当前绑定和冲突状态。

## 6. 控件设计规范（重点：无截图样例控件的推导）

**总规则：控件必须像同一款游戏 UI 的自然延伸。** 对截图中没有直接样例的滑块、进度条、下拉框、复选框等，不允许照搬 ImGui 默认外观；按下面指定的“视觉映射”实现。

### 6.1 Button 按钮

必须提供四种语义样式：

| 类型 | 外观 | 用途 |
|---|---|---|
| `Primary` | 黄色填充 `Yellow500`，深色粗体字，轻微白/金色上缘 | 保存、应用、确认、主要操作 |
| `Secondary` | 深蓝半透明底，浅色细描边，白色文字 | 取消、返回、次级操作 |
| `Tab/Navigation` | 矩形条形底，不做成普通按钮 | 页面切换/分类导航 |
| `Danger` | 暗红/深色底，红色细边或红色强调字 | 重置、删除、危险操作 |

状态必须支持 Normal / Hovered / Active / Focused / Disabled：

- Hovered：亮边/底色略微提亮，必要时增加细青色外沿。
- Active：底色略微压暗，按钮视觉位置可向下偏移 1px，但不能抖动。
- Focused：有清晰青色描边或焦点角标。
- Disabled：降低底色饱和度与亮度，文字仍可辨认；不得只把控件整体调成半透明。
- 黄色只用于真正的 Primary，不得所有按钮都用黄底。
- 危险操作必须有二次确认或明确反馈。

### 6.2 Tab / Navigation 导航

提供两种样式，并按布局场景选择：

**横向 Tab（场景 B 风格）：**
- 默认：深紫黑/深蓝条形底，灰白文字。
- 选中：白色或浅灰底，深色粗体字，底部 3–4px 青色指示线。
- Hover：文字提亮或底色略亮，不得与选中态混淆。
- Disabled：低对比文字，但仍可读。

**纵向分类导航（场景 A 风格）：**
- 默认：深蓝半透明横条，灰蓝文字，左/右边界整齐。
- 选中：蓝青色块或蓝色渐亮底，白色/深色文字根据亮度自动选择；边缘增加 3–4px 青色状态线。
- Hover：仅轻微提亮背景，不能看起来像选中。
- 图标若存在，尺寸、基线和图文间距统一。

切换页面后是否保留滚动位置由功能语义决定；不能让每次切换都无故跳回顶部。

### 6.3 Toggle 开关

- 采用紧凑的横向滑块开关，而不是默认 ImGui Checkbox 的方框样式。
- OFF：深蓝灰轨道、浅蓝/灰色边线，圆形滑块靠左。
- ON：轨道使用 Cyan/Blue，滑块为近白色并靠右；可在轨道上增加低调的亮度变化。
- 状态必须能通过位置和视觉差异识别，不能只靠青/灰颜色。
- 状态文字可选显示“开启/关闭”，但同一页面必须统一。
- 需要异步执行的功能应有 Busy 状态，避免用户重复点击。

### 6.4 Checkbox 复选框

当语义确实是多选时使用 Checkbox，不要把所有布尔值都做成 Checkbox。

- 外形：16–18px 方形，3px 左右轻圆角或轻切角。
- 未选：深蓝底 + 浅蓝细边。
- Hover：边框变亮青色。
- 已选：青蓝色填充或深蓝底配青色勾号；勾号必须清晰。
- Disabled：低饱和底色与文字，但仍能辨认当前值。
- 点击热区应包含旁边标签，不只允许点小方框。

### 6.5 Slider 滑动条（无直接样例，必须按此推导）

- 轨道为 5–7px 高的细长胶囊/轻圆角条，底色 `Navy900` 或低饱和蓝灰。
- 已完成部分使用从 `Blue600` 到 `Cyan500` 的轻微蓝青过渡；不得做彩虹渐变。
- 滑块头为 14–18px 圆形，中心近白色或浅蓝，外圈青色；Hover 时外圈提亮，Dragging 时稍微放大但不超过 1.15 倍。
- 当前数值必须始终可见，放在轨道右侧或标签同一行；单位跟在数值后。
- 精确控制的数值必须支持输入框或步进按钮，避免只靠拖动。
- 有效范围明确；超界输入必须钳制或拒绝并给出反馈。
- 高频/昂贵功能不要在拖动每一帧都提交底层操作；可在释放时提交，或采用有节流的实时预览。
- Hover / Focus 状态使用青色描边；Disabled 轨道、滑块和文字统一降饱和。

### 6.6 ProgressBar 进度条（无直接样例，必须按此推导）

- 轨道高度 8–12px，深蓝半透明底，外沿可有 1px 低透明蓝线。
- 已完成部分使用蓝青色填充，端部轻微圆角；不要使用默认绿色进度条。
- 关键进度值应在条旁显示百分比或“当前/总量”。
- 只有具有明确语义时才用黄色表示接近阈值/重要阶段；危险阈值用红色，但必须同时给文字说明。
- 不确定/循环加载使用低干扰的青色动画，不得持续大面积闪烁。
- 进度更新动画应短且平滑；数值变化必须及时，不得为了动画滞后表达真实状态。

### 6.7 Combo / Dropdown 下拉框（无直接样例，必须按此推导）

- 收起状态：深蓝半透明矩形输入面板，细浅蓝描边；左侧显示当前选项，右侧放青色或浅蓝向下箭头。
- Hover：外边框提亮；Focus/Open：边框使用 `Cyan500`，可增加 1px 外沿。
- 展开列表：浮于其他控件之上，使用更深的 `Navy850/Navy900` 背景与青蓝细描边；不可透明到文字与游戏背景混在一起。
- 普通选项：白色/浅蓝文字；Hover 行使用蓝青半透明底；当前选项使用更明显的蓝色底或左侧青色短条。
- 长列表必须限制最大高度并使用自定义滚动条；支持键盘上下选择、Enter 确认、Esc 关闭。
- 选项文本过长时裁切并提供 Tooltip；不得改变控件宽度造成页面跳动。
- 弹出列表必须正确处理窗口边缘，必要时向上展开。

### 6.8 Input / Text Input 输入框

- 默认背景：深蓝半透明，描边为低亮蓝灰。
- Focus：青蓝 2px 左右描边，背景略微提亮；不要出现浏览器式蓝色默认焦点框。
- Placeholder：使用 `TextMuted`，但不能把 Placeholder 当作字段名称。
- 正常输入文字：使用 `TextMain`；数值输入可右对齐或使用紧凑数字字体。
- Error：使用柔和红/橙红边线，并在下方或 Tooltip 给出可操作的错误说明。
- Disabled：底色和文字降饱和，仍然能看出当前值。
- 长文本需要横向滚动或合理裁切；需要显示完整内容时提供 Tooltip。

### 6.9 Radio 单选项

- 外圈为深蓝底 + 浅蓝边；选中后增加青色圆心或青色内环。
- 多项选择优先纵向或分组排列；横向排列仅用于选项短且数量少的情况。
- 选中状态不能只改变文字颜色。

### 6.10 Stepper / 数值步进

- 结构为 `[-] [value + unit] [+]`，三个区域保持同一基线。
- 加减按钮使用深蓝底、细边框和白/青色符号；Hover 时边框提亮。
- 中间数值字段允许直接输入，数值变化必须遵守 min/max/step。
- 不允许用过大的圆形加减按钮，避免偏离游戏的矩形控件语言。

### 6.11 Scrollbar 滚动条

- 轨道透明或极暗蓝，宽度约 6–8px；不要使用默认浅灰粗滚动条。
- 滑块为半透明蓝青色，Hover 时提高亮度；拖动时可变为 `Cyan500`。
- 拖动热区可以比可见滑块略宽，但不能挡住内容。
- 内容较短时隐藏滚动条或保持极低存在感；禁止出现无意义的常驻粗条。

### 6.12 Tooltip / Toast / Dialog 提示

- Tooltip：深蓝面板、细青色边、白色主文字；可有一行青色标题，不得堆成长文档。
- Toast：小型深蓝信息条，左侧用小图形/状态色表示成功、提醒或错误；不要全屏通知。
- Dialog：遵循场景 C，包含标题、正文、分隔线、明确的 Primary 和 Secondary 操作。
- 弹窗关闭行为统一：关闭图标、Esc 和取消按钮的行为应符合该弹窗语义。
- 重要操作需要确认；普通操作不应过度弹窗打断。

### 6.13 视觉映射总表

| 控件 | 游戏风格映射 | 必须避免 |
|---|---|---|
| Button | 黄色主操作 / 深蓝次操作 | 全部黄按钮、默认 ImGui 按钮 |
| Tab | 深色条 + 白色选中底 + 青色下划线 | 默认小按钮排列 |
| Toggle | 蓝青轨道 + 白色滑块 | 默认 Checkbox 冒充开关 |
| Checkbox | 深蓝方框 + 青色勾 | 默认灰方框 |
| Slider | 深色细轨道 + 青色填充 + 白色/青色圆形滑块 | 默认蓝色粗条或彩虹色 |
| Progress | 深色轨道 + 蓝青填充 + 数值 | 默认绿色进度条 |
| Dropdown | 深蓝输入框 + 青色箭头 + 深蓝弹出列表 | 原生默认 Combo 外观 |
| Input | 深蓝底 + 细边，聚焦青色描边 | 浏览器/系统默认输入框 |
| Scrollbar | 细窄蓝青滑块 | 粗灰滚动条 |
| Dialog | 蓝色渐层 + 青色双描边 + 黄色主按钮 | 普通黑色 ImGui 窗口 |

## 7. 图标、装饰与动效

### 7.1 图标

- 优先使用项目自有图标、用户提供且可合法使用的图标，或许可证兼容的简洁线性图标。
- 图标线宽应统一，通常使用 1.5–2px 的清晰线条；避免一个页面混用填充、描边和像素风图标。
- 图标颜色以白色、浅蓝和青色为主；黄色只用于主要动作或重要状态。
- 图标按钮必须有 Tooltip 或相邻文本说明。
- 不得用不确定是否包含字形的 Unicode 字符代替关键图标。

### 7.2 装饰

允许：细分割线、边角短线、轻切角、少量菱形节点、低对比几何底纹、青色状态点。

限制：

- 装饰不能覆盖文字或控件点击区域。
- 背景网格只作为 5–10% 级别的弱纹理，不得抢占视觉焦点。
- 不要添加无意义的扫描线、粒子流、持续闪烁和大面积模糊光晕。
- 参考图中的金色星级/稀有度装饰只用于有等级语义的项目，不得用来装饰所有功能控件。

### 7.3 动效

- Hover / Active：约 80–140ms 的短反馈。
- 页面切换或弹窗淡入：约 140–220ms，位移幅度很小。
- 进度变化：可平滑过渡，但不能隐藏真实数值。
- 动效使用 delta time 驱动，不能假设固定 FPS。
- 用户可交互状态必须立即响应；禁止为动画延迟点击结果。
- 动效必须可关闭或在低性能模式下自动简化。

## 8. Dear ImGui 工程组织

### 8.1 推荐结构

```text
ui/
  Theme.h / Theme.cpp       // 颜色、字体、尺寸、风格应用
  Tokens.h                  // 统一颜色与尺寸令牌
  Fonts.h / Fonts.cpp       // 字体加载、回退与 DPI 重建
  Widgets.h / Widgets.cpp   // Button、Tab、Toggle、Slider、Combo 等
  Draw.h / Draw.cpp         // 双描边、切角、分隔线、背景纹理
  Layout.h / Layout.cpp     // 主窗口、导航、内容区、状态栏
  Pages/
    HomePage.cpp
    FeaturePage.cpp
    SettingsPage.cpp
    AboutPage.cpp
  State.h                   // UI ViewState / 状态绑定
  Assets.h / Assets.cpp     // 图标与纹理生命周期
```

可以按项目规模合并文件，但必须保持主题、绘制、组件、页面和功能逻辑之间的职责边界。

### 8.2 Theme 参考结构

```cpp
namespace ui {
    struct Palette {
        ImVec4 navy950;
        ImVec4 navy900;
        ImVec4 navy850;
        ImVec4 navy800;
        ImVec4 blue700;
        ImVec4 blue650;
        ImVec4 blue600;
        ImVec4 cyan500;
        ImVec4 cyan300;
        ImVec4 yellow500;
        ImVec4 textMain;
        ImVec4 textMuted;
        ImVec4 danger;
    };

    struct Metrics {
        float uiScale;
        float controlHeight;
        float controlHeightLarge;
        float navItemHeight;
        float spaceS;
        float spaceM;
        float spaceL;
        float radiusSmall;
        float radiusMedium;
        float borderThin;
        float borderEmphasis;
    };

    struct Theme {
        Palette colors;
        Metrics metrics;
    };

    void ApplyTheme(const Theme& theme);
}
```

要求：

- `ApplyTheme()` 在初始化或主题切换时调用，不得每帧反复重置整个 Style。
- 自定义控件统一通过 `Theme` 获取颜色和尺寸。
- 若存在场景 A/B/C 皮肤，使用显式 Theme Profile 切换；不要在单个控件中混用多套色板。
- ImGui 默认 Style 只作为布局和交互基础，最终可见外观必须由统一组件封装覆盖。

### 8.3 自定义绘制

- 使用 `ImDrawList` 绘制双描边、轻切角、横线、状态点和简单纹理。
- 绘制坐标从当前窗口/控件位置计算，遵守 `GetWindowDrawList()` 的裁剪与层级。
- 复杂控件优先复用 ImGui 的交互行为，再自定义绘制外观；不得只画出 Slider 却没有拖动、键盘和焦点语义。
- 不得逐帧分配大量顶点、路径或随机粒子；可缓存静态几何或使用低成本 Primitive。
- 发光仅允许少量低透明度外沿，不得使用多层大范围模糊。
- 自绘控件必须处理鼠标悬停、点击、禁用、焦点、键盘导航和裁剪。

### 8.4 状态与功能接口

推荐采用 ViewState / Controller 分层：

```cpp
struct SettingViewState {
    bool enabled;
    float value;
    bool busy;
    bool valid;
    std::string statusText;
};

class SettingController {
public:
    SettingViewState GetViewState() const;
    bool SetEnabled(bool enabled);
    bool SetValue(float value);
};
```

这只是接口形式示例，必须适配项目现有类型和线程模型。

- 绘制函数读取状态并产生输入意图。
- Controller/业务层负责校验、执行和状态回写。
- 异步任务通过线程安全方式更新 ViewState；UI 线程不得等待。
- 调用失败时恢复真实状态并显示可理解的错误原因。
- 不得让多个页面分别保存同一设置的影子状态。

### 8.5 性能与生命周期

- 字体、图标纹理、静态绘制数据只在初始化或资源重建时加载。
- 避免每帧大量 `new/delete`、文件扫描、磁盘读写、阻塞等待和不必要的字符串构造。
- 大列表使用裁剪/虚拟化。
- Overlay 关闭时跳过页面控件绘制和不必要的计算。
- DPI 变化时按统一流程重建字体和缩放参数，避免控件尺寸不一致。

## 9. AI 执行流程（每次任务强制执行）

### A. 检查现状

先检查现有项目的 ImGui 版本、渲染后端、输入管理、字体加载方式、UI 目录和功能接口。不要假设用户使用某一后端或某个 ImGui 版本。

### B. 确定页面场景

在编码前明确本次页面属于：

- 场景 A：深蓝库存/分类菜单；
- 场景 B：浅灰紫主页/内容卡片；
- 场景 C：蓝色科技详情弹窗。

未特别指定时，主功能菜单用 A，详情/确认弹窗用 C，概览/内容页才考虑 B。

### C. 提取设计要素

根据当前参考图或用户新截图，确认：

- 背景明度和透明度；
- 主色、强调色、语义色；
- 字体字重、字号层级和数字风格；
- 边框、切角、圆角、分隔线；
- 导航选中态和按钮状态；
- 控件密度、间距与对齐。

### D. 先定义令牌，再实现组件

新页面优先复用已有 Theme。若需要新控件，先按第 6 节确定控件映射，再在 Widgets 层封装，不能直接在 Page 中临时拼样式。

### E. 实现顺序

推荐顺序：字体与主题 → 主窗口/导航 → 基础容器 → Button/Tab → Toggle/Checkbox → Slider/Input/Combo → Progress/Scrollbar → Tooltip/Dialog → 页面细节与动效。

### F. 自查

实现后对照参考图检查是否出现：默认 ImGui 痕迹、错误配色、控件圆角不统一、字体过细、信息层级混乱、装饰过度、下拉列表/滚动条默认灰色、数值难辨认等问题。

### G. 不完整信息处理

- 不要重复询问用户已经给出的信息。
- 缺少非关键内容时先做最佳实现，并明确列出假设。
- 如果缺少项目代码，交付可合并的组件实现或清晰的接口示例，不得虚构项目 API。
- 若用户只要求视觉方案，不要擅自改写底层业务逻辑。
